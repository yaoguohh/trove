# 0015 面板内容常驻：隐藏时不卸载，弹入动画交给 Core Animation，卡片时间不再逐秒刷新

- 状态：已采纳
- 日期：2026-11-21
- 依据：取代 [0012](0012-unmount-hidden-panel.md)；下文的测量

## 背景

用户反馈唤出面板"有点卡、掉帧"。在 120Hz 屏幕（一帧 8.3 毫秒）、500 条历史下测量：从按下快捷键到
主线程第一次响应显示刷新约 90 毫秒，每次唤出丢约 15 帧。用 `sample` 采样，原因有三处：

1. **每次唤出重建视图树**（0012 的决定）：`show()` 里 SwiftUI 从零建图、排版、解析文字，约 60–90 毫秒。
2. **弹入动画由 SwiftUI 驱动**：`popIn` 的缩放和位移作用在整块面板内容上，每一帧都在主线程重新生成
   整块面板的绘制列表，动画期间只有约 60fps。
3. **卡片底部的相对时间逐秒刷新**：`Text(date, style: .relative)` 每秒更新一次，每次都让整块面板重新
   排版。面板显示时会带来周期性的顿挫；视图树常驻时，隐藏的面板也会每秒耗约 60 毫秒 CPU。这也是 0012
   观察到"隐藏后仍会排版"的原因。

## 决定

- 面板的 SwiftUI 视图树在隐藏时保留，不再置空；全尺寸图片缓存照旧在隐藏时清空。
- 隐藏期间 `PanelViewModel` 不跟随历史变化，只记下"结果已过期"；下次唤出时在 `prepareForShow` 里
  一次性重算。唤出时的重置（清空搜索、选中第一张、滚回开头）放在禁用动画的事务里，不播放重排和
  滚动动画。
- 内容的弹入动画改由 Core Animation 在承载视图的图层上播放（`NSView.popIn`），视觉参数不变
  （`Motion.scale`、4pt 上浮、`out` 曲线），每一帧由渲染服务器插值，不占主线程。
- 卡片时间按唤出那一刻计算（"5 分钟前"），面板打开期间不刷新。
- 启动后、面板第一次出现之前，预先构建并排版一次面板（`PanelController.prewarm`）。

## 结果

| 指标（热唤出） | 改前 | 改后 |
|---|---|---|
| 到第一次显示刷新 | 约 90 毫秒 | 约 15 毫秒 |
| `show()` 主线程耗时 | 约 60 毫秒 | 约 5 毫秒 |
| 每次唤出丢帧 | 约 15 帧 | 0–1 帧 |
| 隐藏时空闲 CPU | — | 0 |
| 隐藏时每次历史变化 | — | 约 5 毫秒 |
| 内存（唤出 10 次后） | 约 38 MB | 约 31 MB |

启动后的第一次唤出从约 216 毫秒降到约 60 毫秒。

## 放弃的方案

- **保留 0012，只优化单张卡片**：Trove 自己的视图代码在采样里只占几毫秒，成本在 SwiftUI 建图和排版
  本身，减少卡片里的修饰符省不下多少。
- **去掉弹入动画**：可以同样消除丢帧，但会改变设计；改由 Core Animation 实现，外观不变。
- **相对时间用 `TimelineView` 每分钟刷新**：仍会周期性地让整块面板重新排版，而面板通常只打开几秒。

## 后果

- 面板打开期间卡片时间不会变化，下次唤出才更新。
- 隐藏期间新复制的内容不会在面板里播放插入动画，唤出时直接出现在最前面并被选中。
- 视图树常驻会占用少量内存，实测没有超过改前的水平。

## 什么时候重新考虑

隐藏的面板重新出现周期性的 CPU 占用时，例如新增了自动刷新的视图。这时先找到刷新源，不要退回到卸载。
