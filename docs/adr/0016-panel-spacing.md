# 0016 面板间距：一个内边距贯穿四边和工具栏下方，工具栏控件统一高度

- 状态：已采纳（卡片高度随面板变的那一条，以及卡片间距，已被 0020 取代）
- 日期：2026-11-22
- 依据：用户反馈与实测（见"背景"）

## 背景

用户反馈搜索框这一行占比偏大，卡片到搜索框的距离和搜索框到面板顶部的距离差得太多。在 1712×264pt 的
面板上实测：

- 面板顶到搜索框 11pt，搜索框到卡片 20pt，卡片到面板底 20pt；
- 卡片距左右边 25.7pt，工具栏左侧图标约 29pt。

这些值分别来自工具栏的固定内边距（上 8、下 4、左右 22）、36pt 的控件框（里面是 30pt 高的胶囊），
以及 `CardMetrics` 里按面板宽高比例各自算出的卡片边距（上 9–13、下 16–24、左右 16–28），再加上卡片
没有填满时被居中分到上下的余量。没有一条统一的规则，所以处处不等。

## 决定

- 面板用一个内边距 `PanelLayout.inset` = 12pt：面板四边到内容、工具栏到卡片都用它。
- 工具栏控件统一高 `PanelLayout.toolbarHeight` = 28pt，搜索框和收藏板标签的胶囊填满这个高度，图标按钮是
  28pt 的方块。
- 卡片高度 = 工具栏下方的高度减去上下两个内边距，限制在 `CardMetrics.minHeight`–`maxHeight` 之间；
  面板高度上限 = `PanelLayout.chromeHeight` + `CardMetrics.maxHeight`，最小尺寸同理推出。

结果（同一面板）：上下各段都是 12pt，工具栏区从 61pt 降到 52pt，卡片从 183pt 增高到 200pt。

## 放弃的方案

- **16pt 内边距**：同样整齐，但工具栏区只从 61pt 降到 60pt，没有解决"占比偏大"。
- **继续按面板尺寸比例计算边距**：不同屏幕上各段比例不同，正是这次不一致的来源。

## 后果

- 选中卡片的外圈（4pt）离面板边缘还剩 8pt。
- 卡片之间的间距仍按卡片宽度计算（14–22pt），没有并入这一个内边距。

## 什么时候重新考虑

要在面板里加第二行工具栏或底部状态栏时，重新确定竖向节奏。
