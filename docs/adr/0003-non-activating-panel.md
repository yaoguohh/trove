# 0003 面板：不抢激活的悬浮面板，按键在窗口级统一路由

- 状态：已采纳
- 日期：2026-06-04（键盘优先）；2026-06-22（不抢激活）；2026-09-02（窗口级路由）
- 依据：`17c92a8`、`dbb1757`、`7415fa9`

## 背景

面板要能立刻接收键盘输入，关闭后焦点又要回到用户原来所在的应用——那正是粘贴的目标。macOS 14 起
`NSApp.activate(ignoringOtherApps:)` 只是一个"请求"，经常不生效；而抢走激活状态还会让原应用失去前台，
关闭面板后焦点回不去。另外，SwiftUI 搜索框在删除卡片等操作后会丢失焦点，挂在搜索框上的按键处理随之失效。

## 决定

- 面板是 `.nonactivatingPanel`：用 `orderFrontRegardless` + `makeKey` 显示，不激活 Trove，原应用保持
  前台。
- 原应用之外的应用被激活时（⌘-Tab、Spotlight、启动其他应用）面板自动关闭；点到面板之外时由全局鼠标
  监听关闭。这个监听只在面板显示期间存在。
- 所有按键由面板窗口的本地 `keyDown` 监听统一接收，经纯函数 `PanelKeyEvent.decode` 与
  `PanelKeyboard.intent` 决定意图；可打印字符交还给搜索框。输入法组字时不拦截任何键。
- 搜索框与卡片重命名框共用一个 `@FocusState<PanelFocus?>`，同一时刻只有一个获得焦点。

## 放弃的方案

- **激活 Trove 再显示面板**：macOS 14 起不可靠，且关闭后焦点回不到原应用。
- **在搜索框上用 `onKeyPress` 处理导航键**：搜索框失焦后所有导航键失效。

## 后果

原应用聚焦在密码框时，系统的安全输入会把键盘留给那个应用，面板收不到按键；这时可以用鼠标操作面板，
或再按一次快捷键关闭（Spotlight、Alfred、Raycast 也是如此）。

## 什么时候重新考虑

macOS 提供可靠的、不影响原应用前台状态的激活方式时。
