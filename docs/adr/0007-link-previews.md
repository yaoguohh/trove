# 0007 链接预览：自行抓取页面头部，默认关闭

- 状态：已采纳
- 日期：2026-10-30（抓取加固）；2026-11-13（默认关闭）
- 依据：`319bb41`、`7415fa9`；本分支 `e1c7d0e`

## 背景

链接卡片显示网页标题和网站图标会更好认，但抓取意味着向第三方网站发请求：网站会知道这个链接被复制过；
令牌放在路径里的一次性链接（邮箱验证、重置密码）可能仅因为卡片显示出来就被"访问"掉；复制的内网地址还
可能被用来探测内网（SSRF）。

## 决定

- **默认关闭**，用户在状态菜单里打开「链接预览」后才联网；关闭时仍显示已缓存的结果。（2026-11-13 由维护者
  决定，此前默认开启。）
- 请求前去掉查询参数和锚点。
- 自行抓取：只读到 `</head>` 为止（上限 512 KB），图标上限 1 MB，同时最多 4 个请求，单次超时 7 秒。
- SSRF 防护（`LinkAddressGuard`）：拒绝 localhost、`.local`、私有与保留地址的字面量（包括整数和十六进制
  写法）、DNS 解析结果中的私有地址，以及重定向到这些地址。
- 缓存放在 `~/Library/Caches/Trove/link-metadata/`，启动时删除已不在历史里的链接；没有标题也没有图标的
  结果 24 小时后重试。

## 放弃的方案

- **默认开启**：多数用户不会注意到这个开关，隐私风险由用户默默承担。
- **LinkPresentation（`LPMetadataProvider`）**：提交记录里没有写明放弃原因。从实现推断：它会完整加载
  页面，无法去掉查询参数，也无法插入地址检查。
- **保留查询参数**：靠查询参数区分的页面（如 `watch?v=`）会因此显示通用标题，这是为隐私付出的代价。

## 后果

新用户默认看不到链接标题和图标。

## 什么时候重新考虑

如果要为查询参数区分的网站显示准确标题，只能针对用户明确打开预览的情况，并逐个评估查询参数里是否
可能有令牌。
